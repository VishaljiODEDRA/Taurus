# Taurus Build Log: Week 01

Date: 2026-06-07

## Context

This first public build log establishes the Taurus baseline. The project is at the Phase 0 foundation stage: turning a local AI-assisted trading agent into a public-safe fintech infrastructure project focused on risk governance, auditability, model governance, broker reconciliation, and demo/paper validation.

The central product position is deliberately conservative: Taurus is not a profit bot, investment adviser, copy-trading service, managed account, or performance-promise product. It is infrastructure for governing AI-assisted trading workflows before any live or regulated use is considered.

## What Shipped

- Public repository foundation for a local risk-first trading governance engine.
- README positioning Taurus as an AI trading governance platform rather than a trading-performance product.
- Product and engineering planning documents covering product requirements, technical requirements, app flow, backend schema, UI/UX brief, implementation plan, security policy, contribution guidance, and changelog.
- Local CLI workflow through `python3 -m agent` and `run_agent.py`.
- eToro API client and market-data adapters.
- Shadow/demo/live execution modes with strict live gates.
- SQLite ledger and JSONL audit trail for decisions, risk checks, orders, cycle data, model events, reconciliation, reliability, and execution evidence.
- Deterministic risk engine, pre-trade policy, portfolio risk analysis, execution simulation, and kill switch.
- Backtesting, walk-forward validation, calibration, model training, model registry, promotion/rejection events, reliability reports, and replay support.
- Broker reconciliation for position drift, missing orders, duplicate exposure, stale protection, and P&L mismatch detection.

## Technical Decisions

- Keep the first product surface CLI-first while the governance engine is hardened.
- Use deterministic risk gates as the authority layer between model output and broker-facing actions.
- Keep `shadow` mode as a safe default for local research and public demonstrations.
- Require both `AUTOTRADER_ALLOW_LIVE=true` and `--allow-live` before local live execution can be constructed.
- Store local evidence in SQLite and JSONL for transparent inspection, replay, and future dashboard/API work.
- Preserve raw JSON payloads for auditability while also recording normalized fields for reporting and training.
- Treat model training as a governed lifecycle: candidate model, active model, promotion gate, rejection event, reliability report.
- Treat reconciliation as a core product feature, not a back-office afterthought.

## Tests And Verification

The project has a unit test suite covering core research and governance behavior, including chart analysis, market data, shadow engine behavior, eToro client parsing, exits, institutional layers, ML, news, order policy, portfolio logic, readiness, reconciliation, regime classification, reliability, risk, and signal generation.

Current verification status:

- Unit tests run with `python3 -m unittest discover -s tests`.
- Latest local verification for this baseline: 80 tests passing.
- The June foundation work should keep this command passing before public pushes.
- Public logs should record only high-level test status, not private runtime data.

## Demo And Validation Findings

The first validation objective is operational discipline, not trading performance.

Current safe validation workflow:

- run configuration checks,
- inspect data-health,
- run shadow or demo cycles only,
- use the kill switch when uncertain,
- reconcile broker and ledger state,
- generate high-level governance reports,
- publish only redacted weekly summaries.

No profit screenshots or private broker account details should be used as the main story. The credible story is that Taurus records evidence, blocks unsafe actions, and makes model/risk/execution behavior reviewable.

## Safety And Compliance Notes

- No public investment advice.
- No stock recommendations.
- No copy trading.
- No managed accounts.
- No public live execution for beta users.
- No return guarantees.
- No raw ledgers, JSONL audit logs, broker credentials, account IDs, private balances, private positions, or raw broker payloads in public logs.
- Public language should describe paper/demo/research/governance infrastructure.

## Risks And Open Questions

- The project is still local-first and not yet a hosted SaaS application.
- There is no authentication, workspace model, RBAC, hosted database, API, billing, incident system, or GDPR/CCPA workflow yet.
- Local SQLite and file logs are useful for a single-user evidence engine but are not enough for multi-tenant production.
- Broker credential handling must remain private and local until encryption, legal review, and regulated-activity review are complete.
- Public communication must avoid performance framing and stay focused on governance infrastructure.
